# Gate log, 2026-10-19

The runbook (`gate-runbook.md`) run against the real publisher. Each step: what was run, what answered.
Keys and tokens are never written here.

## Setup

- Store: local Postgres, schema `gate_2026_10_19` (its own, so nothing of ME's is touched).
- Host: `node bin/crubal-host.ts serve --port 8787`, domain `gate.localhost`, `CRUBAL_HOST_OF` mapping
  `cashierfu.com` and `mediaencyclopedia.com` to `http://localhost:3100/h` (the Cashierfu app's host on the
  development machine, the adopter's publisher until cashierfu.com is deployed).
- Adopter's publisher: the app's host, after `scripts/publish-shipped.mts` published the 2026-11-11 set
  (bench, channels, commerce, operations, person, platform, product, stacks, storefront at 2026-11-11;
  location 2026-11-07; service 2026-10-16; mediaencyclopedia.com/media 2026-11-11), each signed with the
  owner's key the app's host holds.

## Steps

1. **Publisher.** `GET https://crubal.com/.well-known/crubal.json`: owner crubal.com, one Ed25519 key
   (from 2026-10-15), packages core 2026-10-14, units 2026-10-15, party 2026-10-16 with version URLs.
   `GET https://crubal.com/party/2026-10-16/package.json`: `crubal: 2`, id, version, owner, `hash`, **no
   `sig`**. The same for core and units. Finding: the site was built without `CRUBAL_SIGNING_KEY`.
2. **Host up.** `migrate` → `migrated`; `owner create gate.example` → the owner with its public key;
   `key issue gate.example gate.example` → one key, kept out of this log; `GET /health` →
   `{"ok":true,"domain":"gate.localhost",…}`.
3. **Install by name, first try.** `POST /o/gate.example/install {"package":"cashierfu.com/product"}` as
   the owner → 400 `crubal.com/party: unsigned bundles are refused; a store may allow them for development`.
   The host fetched the adopter's well-known file at the mapped URL, found product extends crubal.com/party
   and cashierfu.com/location, fetched party from crubal.com first, and refused it, correctly. **Stopped.**
   The steward rotated the key the same afternoon (the first pair's private half had never reached the
   build), set `CRUBAL_SIGNING_KEY` in the crubal.com deployment and redeployed; at 16:09 the well-known
   file carried the new public half (from 2026-10-19) and the party bundle its `sig`.
3. **Install by name, second try.** The same request → 200: `crubal.com/party 2026-10-16` from
   `https://crubal.com/party/2026-10-16/package.json` (entry L-1, verified against the published key),
   `cashierfu.com/location 2026-11-07` (L-2) and `cashierfu.com/product 2026-11-11` (L-3) from the adopter's
   host. Then `mediaencyclopedia.com/media 2026-11-11` (L-4). `/health` shows the chain at 4.
4. **Project and serve.** `POST /project` with the host key (the commit had already published inline, the
   host runs `fresh: write`); `GET /o/gate.example/v/shop` → 200, one row (Gate Test Disc),
   `x-crubal-seq: 1`, `x-robots-tag: all` from the terms; `GET /o/gate.example/v/catalog` as the owner →
   200, no row (the media catalog wants a wearer of its classes), counts for format and rating.
5. **A form run.** `GET /o/gate.example/forms/product?level=product` as the owner → the product form,
   origin declared, sections with title required. `POST /o/gate.example/run/product {level, answers}` →
   `arrival: {outcome: new, record: P-1}`, log L-R1, a rule derived `unitCount: 0`; the record read back is
   gate.example's with the declared values.
6. **A send acted and answered.** Not run against the adopter's packages: their sends are adapter-bound
   (eBay, Stripe mail, the bench printer, the marketplace stream) and none names `host:url`, so the
   reference host's built-in `http` adapter has nothing of theirs to act on. The host suite shows the step
   with a test contract (`host.test.ts`, the send with an adapter and an answer).
7. **A scheduled tick.** `POST /tick {"now":"2026-10-19T21:10:00Z"}` with the host key → `[]`: nothing
   due, nothing run twice.
8. **An erasure.** `POST /o/gate.example/erase/P-1` as the owner → `{redacted: 3, witnessed: []}`;
   `POST /project` → 2 entries; the shop and items streams each carry `P-1` at seq 2 with `removed: true`;
   `GET /v/shop` → no row, `x-crubal-seq: 2`; the record read back has empty values.

**The gate is passed** on the adopter's own packages, installed by name from the real publisher. What
follows is the steward's merge of the dated revision, the tag `corpus/2026-10-19`, and the npm publish.

## What unblocked it

The steward set `CRUBAL_SIGNING_KEY` (the private half of the key whose public half is in the well-known
file and `site/build.mjs`) in the crubal.com deployment's environment and redeploys. The build then prints
no `unsigned` warning and each bundle carries `sig`. Then steps 3 to 8 run again from this log's setup.
