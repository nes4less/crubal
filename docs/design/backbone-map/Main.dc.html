CRUBAL 2 backbone
Each piece is a stand-alone tool. Every caller, ours or outside, connects through the border. Inside the core, only its own rules, migrations and instructions also write. Named tools and parties on this map are examples; the core defines none of them.

Outgoing contracts (e.g. a marketplace listing, a feed, a label) run the same border in reverse, with the host resolving each credential by name. The host proves who a caller is; the core decides what that caller may do, and logs that they did it. Indexes subscribe through a stream contract (push or pull, a cursor per view, a reset per view version) and read only projection rows, already filtered for their audience; they serve a caller only the rows their edges match (views above member are partitioned by default), so they can never show what a view leaves out. Every change, data or definition, is one logged entry; the state is what the entries give. They may lag a moment; actions check again against the core through each contract's needs. Placement rule: anything that needs rule semantics or an audience decision is core; anything about performance or presentation is outside.
